## DI

DI 就是依赖注入

```
class orderMapper{}


class orderService{
  constructor(repository) {
    this.repository = repository;
  }

  create() {
    return this.repository.save();
  }
}

// 在外面统一组装
const mapper = new orderMapper();
const service = new OrderService(mapper);
```

## IoC
IoC是控制反转, 原来业务对象自己控制依赖的创建，现在交给外部容器 , DI是实现这种设计的主要方式; 

这种是使用非DI的方式实现的逻辑, service的业务逻辑和依赖绑定在了一起; 
```
class OrderMapper{}
class OrderService{
  constructor(repository) {
  this.repository = new OrderMapper()
  }

  create() {
    return this.repository.save();
  }
}
```
使用IoC是当前项目中如果有几十上百的对象要创建,传统的方式需要一个个手动创建并管理依赖顺序,IoC容器负责创建和管理的工作;

```
@Repository
public class OrderRepository {

    public String save() {
        // 先用字符串模拟保存结果
        return "订单保存成功";
    }
}


@Service
public class OrderService {

    private final OrderRepository repository;

    public OrderService(OrderRepository repository) {
        this.repository = repository;
    }

    public String create() {
        return repository.save();
    }
}
```
